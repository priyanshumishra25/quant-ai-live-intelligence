METHODOLOGY

From evidence to forecast

Each live analysis follows an explicit temporal pipeline. The validation design is intended to avoid future information leaking into the holdout.

  1. 01

    Instrument resolution

    An uppercase ticker can be used directly. Company names are resolved through the configured market-data provider.

  2. 02

    Market history

    Daily OHLCV history is retrieved and converted into return, moving-average, momentum and volatility features.

  3. 03

    News collection

    Market news is collected with provider sentiment and relevance metadata. Invalid timestamps are discarded rather than replaced.

  4. 04

    Trading-session alignment

    News is converted to America/New_York time. Items published at or after the 4:00 PM market close are assigned to the next available market session.

  5. 05

    Feature construction

    Technical and news features are aligned on the market-date index. Evidence outside the available history window is excluded.

  6. 06

    Target definition

    The model predicts forward returns for 1, 5 or 20 trading-day horizons.

  7. 07

    Purged chronological validation

    The holdout is chronological. A horizon-length purge gap separates the training set from validation so training targets cannot overlap the holdout period.

  8. 08

    Regularisation selection

    Ridge alpha is selected from training data only using generalized cross-validation over a declared candidate grid.

  9. 09

    Holdout evaluation

    MAE, directional accuracy, correlation, residual volatility and approximate non-overlapping observations are reported as diagnostics.

  10. 10

    Final refit

    After validation, the selected model is refit on all eligible historical rows to produce the current forecast.

  11. 11

    Uncertainty

    The displayed interval is based on purged holdout residual volatility, not final-fit in-sample residuals.

  12. 12

    Public-discussion overlay

    When Reddit is configured, current discussion is processed at inference time only. Its contribution is bounded to a fraction of holdout residual volatility and does not change fitted coefficients.

  13. 13

    Signal scores

    Bullish, neutral and bearish values are heuristic directional scores. They are explicitly not calibrated probabilities.

  14. 14

    Limitations

    Compact free-tier history can make validation statistically weak, especially at a 20-day horizon. The interface exposes that reliability limitation directly.

MODEL CARD

Model purpose, behaviour and limits

Quant AI is research software for inspecting a forecasting workflow. It does not provide financial advice.

Model purpose

Estimate short-horizon forward returns from historical price features and market-news features, then expose the resulting forecast with validation diagnostics and source evidence.

Intended use

Software engineering demonstrations, ML evaluation, educational research, reproducible experimentation and inspection of temporal validation choices.

Out-of-scope use

Automated trading, portfolio allocation, execution, suitability decisions, personalized financial advice and claims of future profitability.

Inputs

Daily market history, provider-attributed financial news and optional current public Reddit discussion.

Outputs

Predicted return, predicted price, holdout-derived interval, directional signal score, source contribution mix, top drivers and validation diagnostics.

Temporal leakage controls

Chronological holdout, horizon-length purge gap and market-session news alignment are used to reduce look-ahead leakage.

Hyperparameter selection

Ridge alpha is chosen on training data only. The holdout is reserved for evaluation.

Reddit handling

Reddit content is not used to train persistent model weights. Current sentiment is processed as a bounded inference-time signal when authorized API access is configured.

Failure modes

Provider quotas, sparse news, small validation samples, regime changes, ambiguous ticker resolution and missing Reddit access can reduce usefulness.

Interpretation

Directional signal scores are heuristic indicators and are not calibrated probabilities of market outcomes or profit.

SECURITY

Security boundaries are explicit

The public client contains no provider credentials. Secrets are injected into the backend environment and release checks reject tracked local environment files.

Credential handling
Provider keys and JWT secrets stay server-side in environment configuration.
Authentication
The API uses bearer tokens. The browser does not persist the user's password.
Rate limiting
Backend request limits and provider pacing reduce accidental quota exhaustion.
External links
Evidence URLs are restricted to HTTP and HTTPS before rendering.
Release checks
The release script verifies required artifacts, rejects disconnected prototype paths and checks model artifact hashes.
Data retention
Provider evidence is cached for short operational windows. Reddit content is not stored as a persistent training corpus.
Production configuration
Known development credentials and default JWT secrets are rejected in staging and production.

For responsible disclosure, use the repository's security guidance before publishing vulnerability details.

PRIVACY POLICY

Privacy and data handling

Last updated 2 October 2026.

Information processed

The application processes stock or company queries, authentication details needed to access the API, provider responses and operational request metadata.

Market-data providers

Live queries may be sent to configured third-party market-data and news providers. Their handling of those requests is governed by their own terms and privacy policies.

Reddit data

When configured, public Reddit posts and limited comments may be processed for the current analysis. Reddit content is not used to train persistent model weights or maintained as a persistent content corpus by this application.

Authentication information

The browser stores a short-lived access token in session storage. Passwords are kept in memory for the current page session and are not written to session storage by the redesigned client.

Application logs

The backend may record operational logs such as request timing, endpoint status and errors. Do not submit sensitive personal information as a stock query.

Cookies and analytics

The current frontend does not require advertising cookies or third-party analytics.

Retention

Live provider responses may be cached for configured operational time-to-live periods. Retention depends on the deployment environment and cache configuration.

Contact and changes

Questions and change history can be handled through the public repository. This policy should be reviewed if hosting, analytics or data providers change.
